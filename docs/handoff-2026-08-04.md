## Traps worth knowing

- **A blocked Maps key now stops bookings, not just autocomplete.** `/api/cal/book`
  rejects addresses with no resolvable city, so if the dropdown can't load, customers can
  neither pick an address nor type one. Never deploy tighter address validation without
  confirming the production key works first.
- **`PATCH /v2/event-types/{id}` on Cal.com silently drops fields** it claims to
  preserve — it removed `attendeePhoneNumber` and the workflow-managed
  `smsReminderNumber`. Back up the event type and diff afterwards.
- **Google Cloud lists "Places API" and "Places API (New)" as separate entries.**
  Restricting a key to the wrong one silently forces the legacy path.
  `API_KEY_SERVICE_BLOCKED` = the key's restriction list excludes the service; "has not
  been used in project N" = the API isn't enabled on the project. Both can be true.
- **The Vercel CLI login (`erik-3681`) cannot see this project.** It lives under the
  `snapsonic` team as `covecutlery`. Use the `VERCEL_ACCESS_TOKEN` in `.env.local`, which
  authenticates as `erik-4230`.
- **`customers.email` is unique** (409 on conflict), despite not showing in the OpenAPI
  probe. No table holds a `customers.id` foreign key — `bookings` and
  `course_enrollments` denormalize name/email/phone instead.
